What is GPS Tracking?

31+ satellites orbit Earth at ~20,200 km altitude, each broadcasting precise timestamps. Your device receives signals from 4+ satellites simultaneously, calculates the travel time of each signal, and uses trilateration to pinpoint an exact 3D position — latitude, longitude, altitude.

Section 04

What is Geofencing?

A Geofence is an invisible digital boundary drawn on a map. When a device enters or exits this boundary, the system automatically triggers an action — clocking in, sending an alert, or auto-logging attendance.

→ Employee enters geofence = Clock-In ✓
→ Employee exits geofence = Clock-Out ✓
→ 9:30 AM, never entered = Late Alert 🔔
Geofence Event Types
→
ENTRY
Outside→Inside. Triggers: clock-in, start timer, notification
←
EXIT
Inside→Outside. Triggers: clock-out, stop timer, report update
⏱
DWELL
Inside for N minutes. Confirms presence (not a pass-through)
🔔
NO-SHOW
Work time started, device never entered → absence alert
🔵 Circular Geofence
Center + radius. Simple to configure. Uses Haversine formula. Best for office buildings.
🔶 Polygon Geofence
Custom shape. Traces actual campus boundary. Uses Ray Casting algorithm. More precise.
Live Geofence
E1 — INSIDE
Clock-In triggered
E2 — OUTSIDE
Alert / No action

⚠️The Core Problem

Standard desktops & most laptops do NOT contain a GPS hardware chip. GPS requires a dedicated radio receiver — this is hardware. You cannot add it in software. This is a fundamental device limitation.

Our 5-Strategy Desktop Solution
1
WiFi Positioning PRIMARY
Windows Location API → scans nearby WiFi SSIDs → matches Google/Microsoft database → ±15–40m accuracy
2
IP Geolocation FALLBACK
Query ipinfo.io or MaxMind → city-level detection. Used when WiFi unavailable or for VPN detection
3
Manual Check-In
Employee selects "Office / WFH / Client Site". System validates via IP + WiFi cross-check
4
BLE Beacons PHASE 2
Install BLE beacons in office → desk-level precision ±1–3m. Syncs with SEPIA's virtual floor plan
5
Corporate Network Detection
Is device on corporate WiFi SSID or VPN subnet? Binary: In-office vs. remote. Instant & reliable

Types of Geofence Rules
⏰
Time-Based Rules
Active only during work hours (9 AM–6 PM). Entry before 9:30 = On-time. After = Late. Weekend = Ignored.
👤
Role-Based Rules
Managers: flexible. Field staff: strict geofence. WFH staff: network-based detection instead.
🗺️

Office HQ + Client Site + WFH — each zone triggers different time tracking category.
📁
Project-Based Rules
Time at a client location → billed to project automatically. Invoice hours auto-calculated.
🏠
WFH Detection Rule
No physical geofence needed. Uses: Corp VPN subnet + Home WiFi SSID + IP cross-check.
🔢 Haversine Algorithm (Rust)
fn haversine(p1: LatLng, p2: LatLng) -> f64 { let R = 6371000.0; // Earth radius meters let dlat = (p2.lat - p1.lat).to_radians(); let dlng = (p2.lng - p1.lng).to_radians(); let a = (dlat/2.0).sin().powi(2) + p1.lat.cos() * p2.lat.cos() * (dlng/2.0).sin().powi(2); R * 2.0 * a.sqrt().atan2((1.0-a).sqrt()) } // inside = distance < fence.radius_m

1
Network Lost
Sync engine detects connection failure. Switches to offline mode automatically. Zero interruption.
2
Local Buffer Active
All location records + geofence events written to SQLite. Geofence checks continue locally (no network needed).

Sync engine detects connectivity. Uploads buffered records in batches (max 500 events/request).

✓ Compliance proof — employee was at site for audit

Cons & Risks

✗ WiFi accuracy ±40m — may trigger false geofence events
✗ BLE hardware cost — beacon installation needed for Phase 2
✗ VPN breaks IP fallback — remote workers show wrong city
✗ No true GPS on desktop — WiFi positioning is a substitute
✗ Employee pushback risk — adoption if not communicated well
✗ Windows-only Phase 1 — macOS/Linux need separate APIs
Risk Mitigations
Privacy Risk
Show employees their own data. Binary reporting (in-office/not). Work hours only. Consent-first.
WiFi Accuracy Risk
Use larger radius (300m+). Add 5-min dwell before clock-in. Corp network detection as primary.
Employee Pushback Risk
Clear consent flow. Opt-out available. Transparent company policy. Employee FAQ.
VPN Risk
Detect corporate VPN subnet → mark as "Remote/WFH" (not wrong city). Network-first detection.
🏛️
Architect's Final Recommendation

Proceed with implementation. Start with Phase 1 — WiFi Positioning + Corporate Network Detection + Circular Geofencing. This covers 80% of the use case with zero hardware cost. The consent-first architecture and binary reporting ensures privacy compliance out of the box.

Phase 2 (BLE Beacons) should be gated on client demand — not all organizations need desk-level precision. Phase 3 analytics provide long-term differentiation against Hubstaff, Teramind, and other competitors.
