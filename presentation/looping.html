④ Exit Condition — Know When to STOP

Without an exit Claude can loop forever. Define clear stopping criteria.

✅ Success Conditions (ALL must pass)
✓
Build passes
✓
All tests pass
✓
No TypeScript/Java errors
✓
Linter clean (no warnings)
🛑 Safety Net
Maximum 5 iterations — then stop and report
📝 On Stop
Summarize all changes, what passed, what needs attention
Exit Condition Block 
iteration = 0
MAX = 5

while (iteration++ < MAX) {

  implement()
  verify()

  if (
    buildPasses()   &&
    testsPasses()   &&
    noLintErrors() &&
    noTypeErrors()
  ) {
    // SUCCESS - all conditions met
    summarizeChanges()
    break  STOP
  }
}

if (iteration >= MAX) {
  reportStatus()  safety exit
}

🎣 Method 4 — Hooks (Automated Triggers)

Hooks run commands automatically at specific points in the agent lifecycle.

Hook Points
PreToolUse — before file edits
PostToolUse — after file edits
Stop — when Claude finishes
Auto-format, auto-lint, auto-test — loop automation without prompting
.claude/settings.json 
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Write",
      "hooks": [{
        "type": "command",
        "command": "npm test"
      }]
    }]
  }
}
// Flow:
// Claude edits file
// -> npm test runs automatically
// -> Claude reads result
// -> Fixes if failed  (LOOP!)

👥 Method 5 — Sub-Agents (Maker vs Checker)

Multiple Claude instances with distinct roles create a quality pipeline.

🤖
Claude A — Writer
Implements the feature
🔍
Claude B — Reviewer
Code review & quality check
🔒
Claude C — Security
Vulnerability scan
✅
Claude A — Fixer
Applies feedback, loops if needed
Why Maker vs Checker?
A separate Checker Claude reviews with fresh perspective — just like human code review catches blind spots.
Best For
• Critical production features
• Security-sensitive code
• Complex refactoring tasks
• API contract changes
